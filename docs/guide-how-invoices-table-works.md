## 🗺️ ۱. تصویر بزرگ: دو بازیگر اصلی ما کیستند؟

برای درک این سیستم، کل برنامه را مثل یک **شرکت** تصور کن:

1. **فایل `src/App.jsx` (مغز متفکر و انبار داده):**  
   این فایل مثل مدیر شرکت است. تمام فاکتورها، اینکه کدام فاکتورها تیک خورده‌اند، چه متنی جستجو شده و کدام تب باز است، در حافظه این فایل (State) قرار دارد.
2. **فایل `src/components/invoices/InvoicesTable.jsx` (مانیتور و صفحه نمایش):**  
   این فایل هیچ تصمیم‌گیری مستقلی نمی‌کند! فقط لیستی که مدیر به آن می‌دهد را چاپ می‌کند و هر وقت کاربر تیک زد یا روی دکمه‌ای کلیک کرد، فوراً به `App.jsx` خبر می‌دهد.

## 🧠 ۲. متغیرهای استیت (State) در `App.jsx` چیستند؟

در بالای کامپوننت `App.jsx` چند متغیر با هوک `useState` تعریف کردیم:

```jsx
// ۱. انبار اصلی فاکتورها (تمام فاکتورهای موجود در سیستم)
const [invoicesList, setInvoicesList] = useState(INITIAL_INVOICES_DATA);

// ۲. سبد فاکتورهای انتخاب‌شده (آیدی فاکتورهایی که کاربر تیک زده)
const [selectedInvoiceIds, setSelectedInvoiceIds] = useState([]);

// ۳. وضعیت فیلتر انتخابی (همه، در انتظار، پرداخت شده، معوقه...)
const [invoiceStatus, setInvoiceStatus] = useState('all');

// ۴. متنی که کاربر در کادر جستجو تایپ کرده
const [invoiceSearch, setInvoiceSearch] = useState('');
```

---

## 🔍 ۳. جادوی فیلتر زنده: چطور جستجو و دسته‌بندی کار می‌کنند؟

ما هیچ‌وقت به انبار اصلی فاکتورها دست نمی‌زنیم! بلکه یک کپی فیلترشده به نام **`filteredInvoices`** می‌سازیم:

```jsx
const filteredInvoices = invoicesList.filter((inv) => {
  // الف) اگر کاربر یک وضعیت خاص (مثلاً معوقه) را انتخاب کرده:
  if (invoiceStatus !== 'all' && inv.status !== invoiceStatus) {
    return false; // این فاکتور را نشان نده
  }

  // ب) اگر کاربر متنی در کادر جستجو تایپ کرده:
  if (invoiceSearch.trim()) {
    const q = invoiceSearch.trim().toLowerCase();
    const matchId = inv.id.toLowerCase().includes(q);
    const matchClient = inv.client.toLowerCase().includes(q);
    const matchProject = inv.project.toLowerCase().includes(q);
    
    // اگر متن جستجو در شماره فاکتور، نام کارفرما یا نام پروژه نبود:
    if (!matchId && !matchClient && !matchProject) return false;
  }

  return true; // فاکتور از تمام تست‌ها رد شد، پس به کاربر نشان بده!
});
```

### چرا این روش هوشمندانه است؟
چون به محض اینکه کاربر یک حرف تایپ می‌کند یا روی کپسول «معوقه» می‌زند، ری‌اکت فوراً این تابع را اجرا می‌کند و جدول در کسری از ثانیه خلوت می‌شود، بدون اینکه داده‌ای از بین برود!

## ☑️ ۴. چک‌باکس‌ها دقیقاً چطور کار می‌کنند؟

این بخش یکی از سوال‌برانگیزترین بخش‌های کد است. بیایید قدم‌به‌قدم بازش کنیم:

### الف) تیک زدن یک ردیف خاص (`handleSelectRow`):
کاربر روی چک‌باکس فاکتور `INV-1405-08` کلیک می‌کند:

```jsx
const handleSelectRow = (id) => {
  setSelectedInvoiceIds((prev) =>
    prev.includes(id) 
      ? prev.filter((item) => item !== id) // اگر قبلاً بود، تیکش را بردار (حذف از سبد)
      : [...prev, id]                       // اگر نبود، به سبد اضافه کن
  );
};
```
* **سؤال:** جدول از کجا می‌فهمد ردیف باید زرد شود؟
* **پاسخ:** در فایل جدول بررسی می‌شود:  
  `const isSelected = selectedIds.includes(inv.id);`  
  اگر این متغیر `true` باشد، کلاس `bg-retro-yellow/20` به آن ردیف اضافه می‌شود!

---

### ب) چک‌باکس هدر (انتخاب همه - Select All):
کاربر روی چک‌باکس بالای جدول می‌زند تا تمام ردیف‌ها یکجا انتخاب شوند:

```jsx
const handleSelectAll = () => {
  // اگر همین الان همه فاکتورها تیک خورده بودند:
  if (selectedInvoiceIds.length === filteredInvoices.length) {
    setSelectedInvoiceIds([]); // همه را خالی کن (Deselect All)
  } else {
    // در غیر این صورت، آیدی تمام فاکتورهای نمایش داده شده را در سبد بریز:
    setSelectedInvoiceIds(filteredInvoices.map((i) => i.id));
  }
};
```

## ⚡ ۵. نوار زرد عملیات دسته‌جمعی (Bulk Actions Toolbar)

وقتی به جدول نگاه می‌کنی، این تکه کد را می‌بینی:

```jsx
{selectedIds.length > 0 && (
  <div className="bg-retro-yellow border-b-2 border-black ...">
    ...
  </div>
)}
```

این یعنی:
* اگر سبد انتخاب خالی باشد (`selectedIds.length === 0`)، این نوار کلاً مخفی است.
* به محض اینکه حتی **یک فاکتور** تیک بخورد، این نوار زرد نئوبروتال با دکمه‌های «تسویه گروهی»، «خروجی انتخابی» و «حذف گروهی» ظاهر می‌شود!

### وقتی روی «تسویه گروهی» کلیک شود چه رخ می‌دهد؟
تابع `handleBulkAction('paid', ids)` در `App.jsx` صدا زده می‌شود:

```jsx
setInvoicesList((prev) =>
  prev.map((item) =>
    ids.includes(item.id)
      ? { ...item, status: 'paid', statusLabel: 'تسویه شد', isOverdue: false } // آپدیت به تسویه شده
      : item // بقیه فاکتورها دست‌نخورده بمانند
  )
);
```
به همین سادگی، وضعیت تمام فاکتورهای انتخابی از حالت زرد یا قرمز به سبز تبدیل می‌شود!

## 🛠️ ۶. دکمه‌های عملیات سریع هر ردیف (تسویه تک‌کلیکی و حذف)

در آخرین ستون هر ردیف، چند دکمه داریم:

### ۱. دکمه تسویه فوری (`✓`):
این دکمه فقط برای فاکتورهای `pending` (در انتظار واریز) نشان داده می‌شود:
```jsx
{inv.status === 'pending' && (
  <button onClick={() => onMarkAsPaid(inv)}>✓</button>
)}
```
وقتی کلیک کنی، تابع `handleMarkAsPaid` فاکتور را پیدا کرده و وضعیتش را فوراً به `paid` تغییر می‌دهد. همان لحظه دکمه `✓` ناپدید می‌شود و بج سبز «تسویه شد» ظاهر می‌شود!

### ۲. دکمه حذف (`🗑️`):
با کلیک روی سطل آشغال:
```jsx
const handleDeleteInvoice = (inv) => {
  // تمام فاکتورها به جز این فاکتور را نگه دار:
  setInvoicesList((prev) => prev.filter((item) => item.id !== inv.id));
};
```
فاکتور بلافاصله از حافظه حذف شده و از روی جدول غیب می‌شود!

## 🔢 ۷. شمارنده‌های پویا (Dynamic Counts)

چرا در بالای جدول کپسول‌های وضعیت اعدادی مثل (همه: ۷، تسویه: ۳، در انتظار: ۲) را نشان می‌دهند و چطور بعد از حذف یا تسویه فاکتور خودکار کم و زیاد می‌شوند؟

چون این آبجکت بعد از هر تغییر در استیت دوباره محاسبه می‌شود:
```jsx
const dynamicCounts = {
  all: invoicesList.length,
  pending: invoicesList.filter((i) => i.status === 'pending').length,
  paid: invoicesList.filter((i) => i.status === 'paid').length,
  overdue: invoicesList.filter((i) => i.status === 'overdue').length,
  draft: invoicesList.filter((i) => i.status === 'draft').length,
};
```
وقتی یک فاکتور را تسویه می‌کنی، تعداد `pending` یکی کم و تعداد `paid` یکی زیاد می‌شود!

## 💡 ۸. تقلب برای روز مصاحبه (اگر پرسیدند این جدول چطور کار می‌کند؟)

اگر در نمایشگاه کار مصاحبه‌کننده از شما پرسید:  
**«معماری جدول فاکتورهای شما چطور پیاده‌سازی شده؟»**  
کافیست این ۳ نکته کلیدی را بگویید:

1. **جریان داده یک‌طرفه (Uni-directional Data Flow):**  
   «تمام استیت فاکتورها و عملیات CRUD در کامپوننت والد (`App.jsx`) مدیریت می‌شود و کامپوننت جدول (`InvoicesTable`) به عنوان یک کامپوننت ارائه‌دهنده (Presentational) داده‌ها را دریافت و رویدادهای کلیک را از طریق Callback برمی‌گرداند.»
2. **فیلتر محاسباتی بدون جهش داده (Derived State & Immutability):**  
   «ما داده‌های اصلی را تغییر نمی‌دهیم؛ بلکه متغیر `filteredInvoices` به صورت داینامیک و همزمان بر اساس سه پارامتر (وضعیت، متن جستجو و کارفرما) فیلتر می‌شود.»
3. **عملیات دسته‌جمعی با مدیریت آرایه آیدی‌ها (Bulk Selection):**  
   «انتخاب ردیف‌ها با یک آرایه ساده از شناسه فاکتورها (`selectedInvoiceIds`) مدیریت می‌شود که چک‌باکس هدر را به حالت Indeterminate می‌برد و نوار ابزار عملیات گروهی را به صورت مشروط فعال می‌کند.»
