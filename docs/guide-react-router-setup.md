# 🧭 راهنمای جامع: پیاده‌سازی استاندارد صنعتی React Router v6 در پروژه

<div dir="rtl">

سلام! در این بخش، سیستم ناوبری پروژه **FreelanceOS** را از حالت استیت ساده به استاندارد صنعتی **`react-router-dom` (نسخه ۶)** ارتقا دادیم.  
این قابلیت یکی از مهم‌ترین مواردی است که در مصاحبه‌های فنی React از شما سوال می‌شود. بیایید خیلی ساده و کاربردی ببینیم دقیقاً چه کار کردیم و چطور کار می‌کند.

---

## ۱. چه تغییراتی در ظاهر و رفتار برنامه ایجاد شد؟

1. **آدرس‌های واقعی در مرورگر (URL Routing):**
   - آدرس پیشخوان اصلی: `http://localhost:5173/`
   - آدرس صفحه فاکتورها: `http://localhost:5173/invoices`
   - آدرس مشتریان: `http://localhost:5173/clients`
   - آدرس پروژه‌ها: `http://localhost:5173/projects`
2. **کارکردن دکمه‌های Back و Forward مرورگر:**  
   حالا اگر از پیشخوان به فاکتورها بروی و دکمه بازگشت (`←`) مرورگر را بزنی، دقیقاً به پیشخوان برمی‌گردی!
3. **امکان بوکمارک و رفرش (F5):**  
   اگر روی صفحه `/invoices` کلید F5 را بزنی، در همان صفحه فاکتورها باقی می‌مانی.

## ۲. چهار ابزار اصلی React Router که استفاده کردیم:

### الف) `<BrowserRouter>` در فایل `src/main.jsx`:
```jsx
import { BrowserRouter } from 'react-router-dom';

ReactDOM.createRoot(document.getElementById('root')).render(
  <React.StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </React.StrictMode>
);
```
* **وظیفه:** مثل یک آنتن، کل برنامه `<App />` را در بر می‌گیرد تا تمام کامپوننت‌های داخلی بتوانند به آدرس بار مرورگر (History API) دسترسی داشته باشند.

---

### ب) `<NavLink>` و `<Link>` در فایل `src/components/layout/Navbar.jsx`:
قبلاً در نوبار از `<button>` استفاده کرده بودیم و خودمان دستی چک می‌کردیم کدام تب فعال است. حالا از `<NavLink>` استفاده کردیم:

```jsx
<NavLink
  to={item.path}
  end={item.end}
  className={({ isActive }) =>
    `px-3.5 py-1.5 rounded-xl ... ${
      isActive
        ? 'bg-retro-yellow text-black shadow-retro-sm' // اگر در این آدرس هستیم: زرد نئوبروتال
        : 'bg-white text-black hover:bg-neutral-100'    // اگر نیستیم: سفید ساده
    }`
  }
>
  {item.label}
</NavLink>
```
* **جادوی `isActive`:** کامپوننت `NavLink` خودش خودکار آدرس مرورگر را نگاه می‌کند! اگر آدرس مرورگر `/invoices` باشد، خودش `isActive` را برابر `true` قرار می‌دهد و دکمه «فاکتورها» زرد می‌شود!
* **تگ `<Link to="/">`:** برای لوگوی سایت و مسیر راهنما (Breadcrumb) استفاده شد تا بدون رفرش شدن کل صفحه، کاربر را جابه‌جا کند.

---

### ج) `<Routes>` و `<Route>` در فایل `src/App.jsx`:
این بخش مثل **تابلوی راهنمای طبقات یک ساختمان** است:

```jsx
<Routes>
  {/* طبقه اول: آدرس / پیشخوان را نشان بده */}
  <Route path="/" element={<DashboardPage ... />} />

  {/* طبقه دوم: آدرس /invoices صفحه فاکتورها را نشان بده */}
  <Route path="/invoices" element={<InvoicesPage ... />} />

  {/* اگر کاربر آدرس اشتباهی تایپ کرد، برگردان به صفحه اصلی */}
  <Route path="*" element={<Navigate to="/" replace />} />
</Routes>
```

---

### د) هوک `useNavigate` برای تغییر صفحه با کدنویسی:
گاهی می‌خواهیم وقتی کاربر روی یک دکمه کلیک کرد (مثلاً دکمه «مشاهده تمام ۴۲ فاکتور» در جدول پیشخوان)، با کد او را به صفحه فاکتورها ببریم:

```jsx
import { useNavigate } from 'react-router-dom';

const navigate = useNavigate();

// هنگام کلیک روی دکمه:
onClick={() => navigate('/invoices')}
```

## ۳. نکته طلایی مصاحبه: فایل `vercel.json` چیست و چرا حیاتی است؟

وقتی یک برنامه تک‌صفحه‌ای (SPA) با React Router می‌سازیم، در واقع فقط یک فایل فیزیکی به نام `index.html` داریم و مسیرهایی مثل `/invoices` مجازی هستند (توسط جاوااسکریپت در مرورگر ساخته می‌شوند).

* **مشکل:** اگر پروژه را روی سرور (مثل Vercel) آپلود کنی و کاربر مستقیماً آدرس `site.com/invoices` را باز کند یا رفرش کند، سرور دنبال فایلی به اسم `invoices.html` می‌گردد و چون پیدایش نمی‌کند، خطای **404 Not Found** می‌دهد!
* **راه‌حل حرفه‌ای:** ما فایل `vercel.json` را در ریشه پروژه ساختیم:

```json
{
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```
این فایل به سرور می‌گوید: *«هر آدرسی که کاربر درخواست کرد را تحویل `index.html` بده تا خود React Router صفحه درست را نمایش دهد!»*  
(گفتن همین یک نکته در مصاحبه فنی نشان می‌دهد شما تجربه واقعی دیپلوی کردن پروژه‌های صنعتی را دارید!)
